Definición y modificación de datos: DDL y DML

Cómo SQL materializa un esquema relacional y cómo se insertan, actualizan y eliminan datos.

Intuición y concepto

El modelo relacional separa esquema y datos. SQL refleja esa separación:

  • DDL (Data Definition Language) define o modifica la estructura;
  • DML (Data Manipulation Language) modifica las tuplas almacenadas.

CREATE TABLE define la estructura de una tabla; INSERT INTO agrega filas a la instancia. (Silberschatz et al. 2020)

CREATE TABLE

La forma básica es:

CREATE TABLE nombre_relacion (
  atributo1 tipo1,
  atributo2 tipo2,
  ...
);

Para el dominio universitario:

CREATE TABLE Estudiante (
  rut     VARCHAR(12),
  nombre  VARCHAR(100),
  carrera VARCHAR(100),
  PRIMARY KEY (rut)
);

CREATE TABLE Curso (
  codigo   VARCHAR(20),
  nombre   VARCHAR(120),
  creditos INTEGER,
  PRIMARY KEY (codigo)
);

La declaración de PRIMARY KEY se conecta con la definición formal de llave. Estos ejemplos se concentran en la estructura y las llaves primarias; las restricciones entre tablas requieren además especificar la integridad referencial del dominio.

Tipos de datos

Los tipos SQL pueden agruparse en categorías como:

  • numéricos: INTEGER, SMALLINT, FLOAT, …;
  • caracteres: CHAR(n), VARCHAR(n), CLOB, …;
  • binarios: BLOB;
  • booleanos: BOOLEAN;
  • temporales: DATE, TIME, TIMESTAMP, …
AdvertenciaSQL estándar y motores reales

Los nombres, tamaños, conversiones y comportamiento exacto de los tipos dependen del RDBMS. Por ejemplo, distintos motores implementan de manera diferente números en punto flotante, booleanos y tipos de texto. Verifica los tipos soportados por el motor elegido.

Modificar el esquema

Para modificar o eliminar estructuras se usan instrucciones como:

DROP TABLE nombre_relacion;
ALTER TABLE nombre_relacion
ADD COLUMN nuevo_atributo tipo;
ALTER TABLE nombre_relacion
DROP COLUMN atributo;

El soporte concreto de algunas variantes de ALTER TABLE depende del motor y su versión. (Silberschatz et al. 2020)

Insertar tuplas

La forma básica es:

INSERT INTO relacion (atributo1, atributo2, ...)
VALUES (valor1, valor2, ...);

Ejemplo:

INSERT INTO Estudiante (rut, nombre, carrera)
VALUES ('r1', 'Ana', 'Ingeniería Civil');

También podemos nombrar solo algunos atributos:

INSERT INTO Profesor (pid, nombre)
VALUES ('p1', 'Elena');

Si departamento admite NULL y no tiene un valor por defecto distinto, quedará sin un valor conocido. La semántica de NULL se desarrolla por separado.

AdvertenciaNo omitir columnas sin revisar restricciones

Omitir una columna no garantiza que la inserción sea válida: la operación puede fallar si la columna tiene NOT NULL y no posee un valor por defecto compatible.

Actualizar datos

UPDATE relacion
SET atributo1 = valor1,
    atributo2 = valor2
WHERE condicion;

Ejemplo:

UPDATE Estudiante
SET carrera = 'Computación'
WHERE rut = 'r1';

La condición puede seleccionar varias filas. Por eso, una actualización sin el filtro correcto puede modificar más datos de los pretendidos.

Eliminar datos

DELETE FROM relacion
WHERE condicion;

Ejemplo:

DELETE FROM Inscribe
WHERE rut = 'r2'
  AND codigo = 'BD101'
  AND semestre = '2025-2';

De nuevo, WHERE determina qué filas son afectadas.

Esquema teórico y SQL

En el modelo de relaciones nombradas, un esquema especifica nombres de relaciones y sus atributos. CREATE TABLE agrega además información propia de un RDBMS real: tipos, restricciones y otras propiedades de almacenamiento lógico.

Por ello, la correspondencia es conceptual, no una identidad literal:

\[ \text{esquema relacional} \quad\longrightarrow\quad \text{DDL SQL con tipos y restricciones}. \]

Ejemplo mínimo del esquema transversal

CREATE TABLE Profesor (
  pid          VARCHAR(20),
  nombre       VARCHAR(100),
  departamento VARCHAR(100),
  PRIMARY KEY (pid)
);

CREATE TABLE Inscribe (
  rut      VARCHAR(12),
  codigo   VARCHAR(20),
  semestre VARCHAR(10)
);

CREATE TABLE Dicta (
  pid      VARCHAR(20),
  codigo   VARCHAR(20),
  semestre VARCHAR(10)
);

CREATE TABLE Requisito (
  codigo        VARCHAR(20),
  prerrequisito VARCHAR(20)
);

Las restricciones de llave para relaciones multivaluadas y las llaves foráneas deben decidirse desde el modelo conceptual, no solo desde la sintaxis SQL.

Resumen

  • DDL define o modifica el esquema; DML modifica los datos.
  • CREATE TABLE agrega tipos y restricciones a la estructura relacional.
  • INSERT, UPDATE y DELETE alteran la instancia.
  • El soporte exacto de tipos y algunas operaciones de esquema depende del RDBMS.
  • NULL y las llaves tienen semántica propia, desarrollada en las páginas enlazadas.
