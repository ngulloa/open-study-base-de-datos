Agregación, GROUP BY y HAVING

Funciones agregadas, agrupación y filtros sobre grupos en SQL.

Intuición y concepto

Las consultas vistas hasta ahora transforman filas o combinaciones de filas. La agregación responde preguntas sobre colecciones: cuántos elementos hay, cuál es el mínimo, el máximo, la suma o el promedio. Las funciones agregadas, GROUP BY y HAVING permiten formular estas consultas. (Silberschatz et al. 2020)

Usaremos:

Inscribe(rut, codigo, semestre)

Funciones agregadas

Entre las funciones agregadas más comunes están:

  • COUNT: cuenta valores;
  • SUM: suma valores;
  • MAX: obtiene el máximo;
  • MIN: obtiene el mínimo;
  • AVG: calcula el promedio.

Ejemplo: número de registros de inscripción.

SELECT COUNT(*) AS inscripciones
FROM Inscribe;

Una consulta agregada sin GROUP BY produce, conceptualmente, un único grupo formado por las filas que sobreviven a FROM y WHERE.

COUNT(*) y COUNT(atributo)

No son equivalentes si hay NULL:

SELECT COUNT(*)
FROM Profesor;

cuenta filas, mientras

SELECT COUNT(departamento)
FROM Profesor;

cuenta solo valores de departamento que no son NULL.

Agregación y DISTINCT

Para contar códigos distintos:

SELECT COUNT(DISTINCT codigo) AS cursos_con_inscripciones
FROM Inscribe;

El DISTINCT está dentro del agregado. Compáralo con

SELECT DISTINCT COUNT(codigo)
FROM Inscribe;

que no elimina duplicados antes del conteo y, al producir una sola fila agregada, no cumple la intención de contar valores distintos.

Más de un agregado

Podemos calcular varios agregados sobre el mismo conjunto:

SELECT MIN(creditos) AS minimo,
       MAX(creditos) AS maximo,
       AVG(creditos) AS promedio
FROM Curso;

Atributos no agregados

Una consulta como

SELECT codigo, MIN(creditos)
FROM Curso;

mezcla un atributo no agregado con una agregación sin definir cómo se relaciona codigo con el único valor agregado.

AdvertenciaNo depender del comportamiento permisivo de SQLite

SQLite acepta columnas no agrupadas ni agregadas, llamadas «bare columns», en consultas como la anterior; PostgreSQL rechaza este ejemplo. En SQLite, un único MIN o MAX incorporado vincula esas columnas con una fila que alcanza el extremo, pero los empates pueden dejar ambigüedad. Esta regla particular no debe asumirse en SQL portable. Véanse las reglas de columnas no agrupadas de SQLite y de agrupación de PostgreSQL.

Para escribir SQL portable, todo atributo seleccionado en una consulta agrupada debe estar justificado por la agrupación o por una agregación según las reglas del motor y del estándar aplicable.

GROUP BY

GROUP BY divide las filas en grupos según uno o más atributos y calcula agregados por grupo.

Número de inscripciones por curso:

SELECT codigo, COUNT(*) AS n
FROM Inscribe
GROUP BY codigo;

Conceptualmente, cada grupo se evalúa por separado y aporta una fila de resultados agregados.

Agrupación por varios atributos

SELECT codigo, semestre, COUNT(*) AS n
FROM Inscribe
GROUP BY codigo, semestre;

Cada combinación distinta de codigo y semestre define un grupo.

WHERE versus HAVING

WHERE filtra filas antes de agrupar; HAVING filtra grupos.

Ejemplo: cursos con al menos dos inscripciones en 2025-2.

SELECT codigo, COUNT(*) AS n
FROM Inscribe
WHERE semestre = '2025-2'
GROUP BY codigo
HAVING COUNT(*) >= 2;
  • WHERE semestre = '2025-2' elimina filas de otros semestres;
  • GROUP BY codigo forma grupos;
  • HAVING COUNT(*) >= 2 descarta grupos pequeños.

Orden lógico de procesamiento

Sin HAVING, el orden conceptual es

\[ \texttt{FROM}\to\texttt{WHERE}\to\texttt{GROUP BY}\to\texttt{SELECT}. \]

Al incorporar HAVING, la lectura pedagógica queda:

\[ \begin{aligned} \texttt{FROM}&\to\texttt{WHERE}\to\texttt{GROUP BY}\\ &\to\texttt{HAVING}\to\texttt{SELECT}. \end{aligned} \]

ORDER BY se aplica posteriormente a la presentación ordenada del resultado. Esta secuencia ayuda a entender por qué WHERE no puede filtrar directamente sobre un agregado calculado después de agrupar. (Silberschatz et al. 2020)

Cuándo mover una condición de HAVING a WHERE

Una condición sobre un atributo de agrupación puede aplicarse antes de agrupar cuando selecciona grupos completos y no depende de agregados. El siguiente caso usa una igualdad sobre codigo:

Estas dos consultas expresan la misma intención:

SELECT codigo, COUNT(*)
FROM Inscribe
GROUP BY codigo
HAVING codigo = 'BD101';
SELECT codigo, COUNT(*)
FROM Inscribe
WHERE codigo = 'BD101'
GROUP BY codigo;

La segunda filtra antes de formar grupos y deja más clara la separación entre condición de fila y condición agregada.

El propósito principal de HAVING aparece cuando la condición depende de un agregado:

SELECT codigo, COUNT(*) AS n
FROM Inscribe
GROUP BY codigo
HAVING COUNT(*) >= 2;

Agregación y álgebra relacional

La agregación no forma parte de los operadores del álgebra relacional clásica. Para representarla algebraicamente se necesitan operadores adicionales. Database Theory trata agregados y agrupación como una extensión expresiva posterior. (Arenas et al. 2022)

Resumen

  • Los agregados calculan información sobre conjuntos de filas.
  • COUNT(*) cuenta filas; COUNT(A) ignora NULL en A.
  • AGG(DISTINCT A) elimina duplicados antes de agregar.
  • GROUP BY crea grupos; HAVING los filtra.
  • WHERE actúa antes de la agrupación.
  • Evita consultas no portables que mezclen columnas no agrupadas con agregados.
