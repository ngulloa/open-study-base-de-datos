Consultas SQL: SELECT-FROM-WHERE, joins y conjuntos

El núcleo de DQL y su relación con selección, proyección, producto y join del álgebra relacional.

Intuición y concepto

SQL es declarativo: especificamos el resultado deseado y el RDBMS decide cómo obtenerlo. El núcleo de las consultas combina SELECT, FROM y WHERE, y se amplía con joins y operadores de conjuntos. (Silberschatz et al. 2020; Ramakrishnan y Gehrke 2003)

Estudiante(rut, nombre, carrera)
Curso(codigo, nombre, creditos)
Inscribe(rut, codigo, semestre)

SELECT-FROM-WHERE

La estructura básica es:

SELECT [DISTINCT] lista_atributos
FROM lista_relaciones
WHERE condicion;

Conceptualmente:

  • FROM determina las relaciones de entrada;
  • WHERE filtra combinaciones de tuplas;
  • SELECT determina qué atributos aparecen en la salida;
  • DISTINCT elimina duplicados.

Selección y proyección

SELECT nombre
FROM Estudiante
WHERE carrera = 'Computación';

corresponde, ignorando por un momento la diferencia de duplicados, a

\[ \pi_{nombre} \left( \sigma_{carrera=\text{Computación}}(Estudiante) \right). \]

SQL permite duplicados

En el álgebra relacional una relación es un conjunto. SQL, en cambio, puede conservar filas repetidas. La proyección permite observar esta diferencia.

Si dos estudiantes tienen la misma carrera:

SELECT carrera
FROM Estudiante;

puede retornar Computación más de una vez.

Para obtener el comportamiento de conjuntos:

SELECT DISTINCT carrera
FROM Estudiante;
AdvertenciaNo insertar DISTINCT por costumbre

DISTINCT cambia la semántica de la consulta y puede tener costo. Debe usarse cuando la eliminación de duplicados forma parte del resultado que queremos declarar.

Alias

Un alias permite renombrar atributos o relaciones dentro de una consulta:

SELECT E.nombre AS estudiante
FROM Estudiante AS E;

Cuando dos relaciones tienen atributos con el mismo nombre, calificarlos evita ambigüedad:

SELECT E.nombre, C.nombre
FROM Estudiante AS E, Curso AS C;

Un alias identifica una aparición de una tabla dentro de la consulta. Permite calificar sus columnas, como en E.rut, y distinguirlas de las de otra aparición de la misma tabla.

Producto cartesiano en FROM

La forma

SELECT ...
FROM R, S;

genera conceptualmente combinaciones de filas de ambas relaciones. Si hay nombres de atributos repetidos, deben calificarse. En el álgebra de relaciones nombradas se necesitan renombramientos para formar un producto cartesiano cuando los conjuntos de atributos no son disjuntos.

En la práctica, un producto cartesiano sin una condición que lo justifique suele producir muchas filas y puede indicar un join incompleto.

Joins

SQL permite expresar joins de varias formas.

NATURAL JOIN

SELECT nombre, codigo, semestre
FROM Estudiante
NATURAL JOIN Inscribe;

Compara todos los atributos de igual nombre —aquí rut— y mantiene una sola copia de ellos.

JOIN ... USING

SELECT E.nombre, I.codigo, I.semestre
FROM Estudiante AS E
JOIN Inscribe AS I USING (rut);

Explicita qué atributo compartido debe usarse.

JOIN ... ON

En este sitio preferiremos JOIN ... ON cuando la condición de unión sea explícita:

SELECT E.nombre, I.codigo, I.semestre
FROM Estudiante AS E
JOIN Inscribe AS I
  ON E.rut = I.rut;

Para este inner join, la forma equivalente con una condición en WHERE es:

SELECT E.nombre, I.codigo, I.semestre
FROM Estudiante AS E, Inscribe AS I
WHERE E.rut = I.rut;

Ambas separan correctamente las copias de atributos mediante alias; JOIN ... ON hace más visible qué condición pertenece al join.

Join más filtro

SELECT E.nombre
FROM Estudiante AS E
JOIN Inscribe AS I
  ON E.rut = I.rut
WHERE I.codigo = 'BD101';

En álgebra, bajo semántica de conjuntos (usa SELECT DISTINCT para la misma eliminación de duplicados en SQL):

\[ \pi_{nombre} \left( \sigma_{codigo=\text{BD101}} (Estudiante\bowtie Inscribe) \right). \]

Operadores de conjuntos en SQL

Los operadores de conjuntos y sus variantes con multiplicidades son:

Q1 UNION Q2
Q1 UNION ALL Q2
Q1 INTERSECT Q2
Q1 INTERSECT ALL Q2
Q1 EXCEPT Q2
Q1 EXCEPT ALL Q2

El principio general es que ambos lados deben producir el mismo número de columnas y tipos compatibles. Las variantes ALL conservan multiplicidades cuando el dialecto las soporta; su disponibilidad no es uniforme entre motores.

UNION versus UNION ALL

UNION elimina duplicados del resultado combinado; UNION ALL los conserva.

Ejemplo:

SELECT rut
FROM Inscribe
WHERE codigo = 'BD101'
UNION
SELECT rut
FROM Inscribe
WHERE codigo = 'PROG201';

retorna cada RUT una sola vez.

INTERSECT

SELECT rut
FROM Inscribe
WHERE codigo = 'BD101'
INTERSECT
SELECT rut
FROM Inscribe
WHERE codigo = 'PROG201';

expresa estudiantes inscritos en ambos cursos.

EXCEPT

Una combinación inválida por cantidad de columnas sería, por ejemplo:

SELECT rut, nombre
FROM Estudiante
EXCEPT
SELECT rut
FROM Inscribe;

Los dos lados de un operador de conjuntos deben entregar el mismo número de columnas y tipos compatibles. Para expresar «estudiantes sin ninguna inscripción» proyectamos el RUT en ambos lados:

SELECT rut
FROM Estudiante
EXCEPT
SELECT rut
FROM Inscribe;

Ahora ambos lados producen una sola columna rut; el resultado son RUT presentes en Estudiante y ausentes en Inscribe.

SQL, álgebra y lógica

Para condiciones conjuntivas, sin nulos y eliminando duplicados, el patrón básico se resume como:

\[ \begin{aligned} &\texttt{SELECT DISTINCT ... FROM ... WHERE ...}\\ &\quad\leftrightarrow\quad\pi_{\bar x}(\sigma_\theta(R_1\times\cdots\times R_k))\\ &\quad\leftrightarrow\quad Q(\bar x)\leftarrow\exists\bar y.\; R_1(\bar t_1)\land\cdots\land R_k(\bar t_k)\land\theta. \end{aligned} \]

Esta correspondencia se desarrolla formalmente en equivalencia y patrones de consulta.

Resumen

  • SELECT, FROM y WHERE corresponden naturalmente a proyección, combinación y selección.
  • SQL usa semántica de duplicados; DISTINCT permite eliminarlos explícitamente.
  • Los alias desambiguan atributos y permiten trabajar con varias copias de relaciones.
  • Los joins pueden escribirse de varias formas; una condición explícita evita combinaciones accidentales.
  • UNION, INTERSECT y EXCEPT conectan SQL con operadores de conjuntos.
