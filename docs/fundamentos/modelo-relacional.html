Modelo relacional: tuplas, relaciones, esquemas y bases de datos

Construcción formal del modelo relacional desde tuplas y producto cartesiano hasta esquemas y bases de datos.

Intuición y concepto

El modelo relacional representa la información mediante relaciones. Antes de introducir atributos con nombre, la Clase 01 construye el modelo desde objetos matemáticos simples: tuplas, producto cartesiano, relaciones, esquemas y bases de datos. (Riveros 2026)

Usaremos el dominio universitario como ejemplo transversal. En su forma posicional, una tupla de estudiante puede representarse como

[ (r1, , ). ]

Aquí la posición 1 representa el RUT, la posición 2 el nombre y la posición 3 la carrera. En la página de relaciones nombradas reemplazaremos esta dependencia de posiciones por atributos explícitos.

Tuplas

NotaDefinición formal

Una (k)-tupla (t) es una secuencia ordenada de (k) elementos:

[ t := (a_1,a_2,,a_k). ]

Cuando (k=0), (t=()) es la tupla vacía. (Riveros 2026; Arenas et al. 2022)

El orden y la repetición importan en una tupla:

[ (a,b,c)(c,b,a), (a,a,b)(a,b). ]

En cambio, en un conjunto el orden y la multiplicidad no importan.

Para (t=(a_1,,a_n)), el curso usa:

  • (t[i]=a_i) para el elemento en posición (i);
  • ({t}={a_1,,a_n}) para el conjunto de elementos mencionados por la tupla. (Riveros 2026)

La tupla vacía no debe confundirse con el conjunto vacío:

[ (), {()}. ]

Producto cartesiano

Para conjuntos (A_1,,A_k), el producto cartesiano es

[ A_1A_k := {(a_1,,a_k)a_iA_ii}. ]

Es el conjunto de todas las (k)-tuplas que pueden formarse tomando un elemento de cada conjunto. (Riveros 2026)

Para un conjunto (A), la notación del curso es

[ A^k=_{k}, A^0={()}. ]

Relaciones

NotaDefinición formal

Una (k)-relación (R) es un conjunto finito de (k)-tuplas. En particular, para conjuntos apropiados (A_1,,A_k):

[ RA_1A_k. ]

(Riveros 2026)

Por ejemplo, una relación posicional Estudiante puede ser

[ {(r1,,), (r2,,), (r3,,)}. ]

Como una relación es un conjunto:

  • no tiene un orden intrínseco entre sus tuplas;
  • no contiene la misma tupla más de una vez.
AdvertenciaRelaciones, tablas y orden

La Clase 01 contrasta las relaciones matemáticas con una representación tabular, indicando que una tabla puede mostrar filas en un orden y puede contener filas repetidas. (Riveros 2026)

En SQL, sin embargo, el orden de las filas de una consulta no está garantizado sin ORDER BY. Por eso, en este sitio distinguiremos siempre entre el objeto matemático —la relación— y su visualización concreta como tabla.

Esquema relacional

Sea Data un conjunto fijo de datos posibles. La Clase 01 define un esquema mediante los nombres de las relaciones y sus aridades. (Riveros 2026)

NotaDefinición formal

Un esquema de base de datos es un par

[ S=(N,ar), ]

donde:

  • (N) es un conjunto de nombres de relaciones;
  • (ar:NN) asigna a cada nombre su aridad. (Riveros 2026)

Para el ejemplo universitario, una parte del esquema puede representarse por

[ N={,,} ]

con

[ ar()=3, ar()=3, ar()=3. ]

El esquema describe la forma de la base de datos, no sus valores actuales.

Base de datos de un esquema

Sea Rel el conjunto de todas las relaciones finitas sobre Data:

[ Rel={RRData^k, |R|<kN}. ]

NotaDefinición formal

Dado un esquema (S=(N,ar)), una base de datos (D) de (S) es una función

[ D:NRel ]

tal que, para cada (RN),

[ D(R)Data^{ar(R)}. ]

(Riveros 2026)

Así, D(Estudiante) es la relación concreta almacenada para ese nombre, mientras que ar(Estudiante)=3 pertenece al esquema.

Dominio de la base de datos

La Clase 01 define el dominio activo de una base de datos como los datos que efectivamente aparecen en sus relaciones:

[ Dom(D) := {RN} {tD(R)} {t}. ]

Esta noción será importante al definir la semántica de las consultas de primer orden. (Riveros 2026)

Forma y contenido

La distinción esencial es:

  • esquema: estructura relativamente estable de la base de datos;
  • base de datos o instancia: relaciones concretas que cumplen ese esquema en un momento dado.

Esta separación entre esquema e instancia es estándar en el modelo relacional y reaparece en SQL cuando CREATE TABLE define estructura e INSERT, UPDATE y DELETE modifican datos. (Silberschatz et al. 2020; Ramakrishnan y Gehrke 2003)

Resumen

  • Una tupla es una secuencia ordenada; una relación es un conjunto finito de tuplas.
  • Las relaciones no tienen duplicados ni orden intrínseco.
  • El esquema (S=(N,ar)) define nombres y aridades.
  • Una base de datos (D) asigna a cada nombre una relación compatible con el esquema.
  • (Dom(D)) contiene los datos que aparecen efectivamente en la instancia.
