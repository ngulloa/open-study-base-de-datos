NULL y lógica de tres valores

Semántica de NULL en SQL, UNKNOWN, tablas de verdad y consecuencias para WHERE, agregación y subconsultas.

Intuición y concepto

En una base de datos real puede faltar información. SQL usa NULL como marcador especial para representar situaciones que suelen interpretarse como «desconocido» o «no aplicable». La Clase 06 advierte inmediatamente que estas interpretaciones no son idénticas y pregunta cuál es realmente la semántica de NULL. (Riveros 2026a)

Por eso, NULL no debe tratarse como una constante ordinaria. En particular:

NULL = NULL

no se evalúa como verdadero.

Crear y detectar NULL

Una inserción puede escribirlo explícitamente:

INSERT INTO Profesor (pid, nombre, departamento)
VALUES ('p9', 'Alex', NULL);

También puede aparecer al omitir una columna que admite NULL y no tiene otro valor por defecto.

Para preguntar por el marcador se usan predicados especiales:

SELECT pid, nombre
FROM Profesor
WHERE departamento IS NULL;
SELECT pid, nombre
FROM Profesor
WHERE departamento IS NOT NULL;

No se debe reemplazar IS NULL por = NULL. (Riveros 2026a)

Evitar nulos cuando el dominio no los necesita

SQL permite declarar:

CREATE TABLE Profesor (
  pid          VARCHAR(20) NOT NULL,
  nombre       VARCHAR(100) NOT NULL,
  departamento VARCHAR(100)
);

NOT NULL prohíbe el marcador en una columna. La decisión debe responder al significado del dato: si un valor es obligatorio en el dominio, permitir NULL crea estados que luego deben manejar todas las consultas. (Riveros 2026a)

Lógica de tres valores

Con NULL, SQL no usa únicamente TRUE y FALSE. Introduce un tercer valor lógico:

[ UNKNOWN. ]

La Clase 06 define las comparaciones ordinarias con NULL como UNKNOWN, salvo predicados especiales como IS NULL. (Riveros 2026a)

Estas tablas explican resultados que serían imposibles bajo lógica clásica. (Riveros 2026a; Ramakrishnan y Gehrke 2003)

Operaciones y comparaciones

La regla pedagógica presentada en clase es:

[ NULL  a = NULL ]

para muchas operaciones ordinarias, y

[ NULLa = UNKNOWN ]

para comparaciones ordinarias. (Riveros 2026a)

Por ejemplo:

NULL + 3          -> NULL
NULL = 3          -> UNKNOWN
NULL = NULL       -> UNKNOWN
NULL IS NULL      -> TRUE

Hay excepciones definidas por operadores o funciones específicos; no conviene extender estas reglas mecánicamente a toda función de cada motor.

Semántica de WHERE

NotaRegla clave del curso

Una fila pasa el filtro WHERE si y solo si la condición se evalúa como TRUE. Tanto FALSE como UNKNOWN quedan fuera del resultado. (Riveros 2026a)

Esto explica por qué una aparente tautología clásica puede fallar:

SELECT pid
FROM Profesor
WHERE departamento = 'Computación'
   OR departamento <> 'Computación';

Si departamento es NULL, ambas comparaciones son UNKNOWN:

[ UNKNOWNUNKNOWN=UNKNOWN, ]

y la fila no pasa WHERE.

El problema de NOT IN

La Clase 06 muestra un caso oficial en que una subconsulta usada por NOT IN contiene NULL. Para un valor (x) distinto de las constantes conocidas:

[ \[\begin{aligned} x\;NOT\ IN\;\{NULL,1610\} &=NOT(x=NULL\lor x=1610)\\ &=NOT(UNKNOWN\lor FALSE)\\ &=UNKNOWN. \end{aligned}\]

]

Como WHERE solo conserva TRUE, el resultado puede ser vacío. (Riveros 2026a)

AdvertenciaPatrón seguro para ausencia

Si la intención es «no existe una fila relacionada», NOT EXISTS suele ser una formulación más directa y evita que un NULL en la columna de comparación de la subconsulta contamine un NOT IN.

NULL y agregación

La Clase 05 muestra que:

COUNT(*)

cuenta filas, mientras

COUNT(departamento)

no cuenta las filas donde departamento es NULL. (Riveros 2026b)

Otros agregados también tienen reglas respecto de NULL; para esta primera versión nos limitamos a la distinción explícitamente trabajada en el curso.

NULL no es todavía una teoría completa de información incompleta

La lógica de tres valores describe cómo SQL evalúa expresiones con NULL, pero no resuelve por sí sola preguntas como «¿qué mundos completos son compatibles con esta tabla?». La segunda parte de Clase 06 introduce una semántica formal mediante tablas de Codd y mundos posibles. (Riveros 2026a)

Resumen

  • NULL es un marcador especial, no una constante ordinaria.
  • Para probarlo se usan IS NULL e IS NOT NULL.
  • SQL incorpora UNKNOWN además de TRUE y FALSE.
  • WHERE conserva únicamente filas cuya condición es TRUE.
  • NOT IN puede comportarse de manera sorprendente si la subconsulta contiene NULL.
  • La semántica de mundos posibles permite estudiar información incompleta de forma más rigurosa.
